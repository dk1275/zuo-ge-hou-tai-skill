# 保存可靠性、媒体与部署

## 防重复保存

- 保存按钮进入 `saving` 状态并禁用；请求结束无论成功失败都恢复。
- 同一资源使用前端请求锁，服务端用幂等键或版本号防止竞态。
- 保存前读取旧记录；核心身份字段的空输入不能覆盖已有值，真正的“清空”必须由显式操作表达。
- 成功以后以服务端返回的 ID 和版本更新本地状态；失败不追加本地假记录。
- 分页刷新、导入和同步按稳定 ID 合并/替换，不能无条件 append。

## 错误与回退

区分 `UNAUTHORIZED`、`FORBIDDEN`、`NOT_FOUND`、`INVALID_FIELD`、`CONFLICT`、`RATE_LIMITED` 和 `INTERNAL_ERROR`。错误提示要能指导用户修复；日志记录请求 ID、动作和错误码，不记录密钥和正文隐私。

## 部署迁移

上线前记录函数/服务名称、环境、运行时、入口、资源、依赖安装方式、环境变量名称和触发器。对于不能原地修改运行时的云函数：

1. 先确认尚未上线或准备维护窗口。
2. 用 dry-run 核对删除目标，保留本地源码、配置和回滚依据。
3. 删除并按同名/同入口重建，显式指定新运行时和依赖安装方式。
4. 读取线上实际详情确认 Runtime、Handler、资源、状态和触发器。
5. 调用真实只读接口，再调用一个安全的失败路径，确认代码版本和错误码。

不要把 CLI 输出的“配置更新成功”当作运行时已变更，必须以线上详情为准。部署配置应纳入版本控制，环境 ID 通过参数传入；禁止把正式环境硬编码进导入脚本。

## 回滚

保留上一版源码/构建物、函数配置摘要、数据库迁移前快照和媒体清单。回滚顺序是停止写入或切换维护页、恢复代码/运行时、恢复兼容配置、做只读健康检查、再开放写入。数据库不能用破坏性清空回滚，优先使用事务或快照恢复。
