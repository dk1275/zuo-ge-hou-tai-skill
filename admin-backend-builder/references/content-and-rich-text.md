# 内容模型与富文本处理

## 目标

让“录入、编辑、预览、保存、发布、客户端展示”读取同一份规范化内容，而不是互相猜字段。

## 推荐分层

```text
原始输入 → schema 校验/规范化 → 领域对象 → API payload → 持久化
                                      ↘ 预览渲染
                                      ↘ 客户端渲染
```

- 原始输入可以来自表单、导入或 AI，但进入业务层前必须校验类型、长度、枚举和关联 ID。
- 领域对象保存稳定 ID、顺序、版本和状态。不要用名称、数组下标或展示文案做关联键。
- API 只接收白名单字段；系统字段（创建者、审核者、时间、发布状态等）由服务端写入。

## 富文本与结构化模块

优先保存结构化模块，例如 `overview`、`timeline`、`place`、`restaurant`、`budget`、`warning`；长文本保留字符串版本作为兼容回退。每个模块必须有稳定 `id`、合法 `type` 和可校验的内容。模块数组应限制数量和序列化大小。

不要在回填时把未知模块直接丢掉。可选策略是保留 `unknown` 模块或将其放入扩展字段，并在界面提示人工处理。保存失败时保留当前表单和草稿，不能用空对象覆盖云端。

## 常见富文本坑与一次性防线

| 坑 | 根因 | 防线 |
| --- | --- | --- |
| 标题保存后再打开为空 | 编辑器初始化晚于回填、payload 取错字段或空值覆盖旧值 | 编辑时先取原记录；核心字段空值保护；保存后按 ID 云端回读；加入“关闭再打开”回归测试 |
| 结构化模块看似丢失 | 键顺序、旧字段、布尔值形态被错误比较 | 比较规范化后的语义对象，不比较 JSON 文本或键顺序 |
| AI 自动填表覆盖人工内容 | AI 返回字段不完整却整对象替换 | 只合并通过 schema 的字段；空值不覆盖已有核心字段；保存前显示变更摘要 |
| 预览和客户端不一致 | 预览自己拼字段，客户端又有另一份映射 | 预览和客户端共用展示契约/渲染器；建立快照或关键字段回归 |
| 图片上传后预览失效 | 临时文件地址、`cloud://`、HTTPS URL 混用 | 媒体层统一引用格式；上传完成拿稳定 ID/URL；渲染前区分临时态和持久态 |
| XSS 或危险 HTML | 富文本直接 `innerHTML` | 默认转义文本；只允许经过白名单清洗的标签/属性；禁止脚本、事件属性和危险 URL |

## 回填顺序

1. 拉取服务端记录并校验响应形状。
2. 规范化兼容字段（例如历史数组/字符串）到领域对象。
3. 初始化 schema 默认值，再用领域对象覆盖。
4. 所有关联下拉框加载完成后再设置关联 ID；若关联不存在，显示明确的失效状态，不静默改成第一个选项。
5. 预览消费同一个领域对象。

## 发布前最小规则

标题/名称、所属对象、适用范围、摘要、正文或结构化模块、配图、关联对象和状态必须逐项校验。关联的餐厅/地点必须属于当前父对象；发布失败应返回字段级错误并保留草稿。
