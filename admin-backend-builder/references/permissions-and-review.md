# 权限、登录与审核

## 权限模型

定义“主体—资源—动作—条件”矩阵，而不是只做一个 `isAdmin`：

| 动作 | 典型角色 | 服务端要求 |
| --- | --- | --- |
| 列表/详情 | 编辑、管理员 | 有效会话 + 资源可读 |
| 新增/编辑草稿 | 编辑、管理员 | 有效会话 + 字段白名单 |
| 审核/发布 | 编辑、管理员或更高角色 | 状态可迁移 + 发布校验 |
| 删除/账号/日志 | 管理员 | 更高角色 + 二次确认/审计 |

客户端可以根据角色隐藏按钮，但每个接口仍必须独立鉴权、校验角色和资源状态。不要接受客户端传来的 `createdBy`、`reviewerId`、`_openid`、`status` 等受保护字段。

## 登录与会话

- 登录失败、云端同步失败、会话恢复失败时保持锁定，不要因为本地缓存存在就解锁。
- 密码只存强哈希和随机盐；会话令牌只存摘要，设置过期、撤销和失败限流。
- 不把 API Key、AppSecret、密码、真实身份标识写入前端源码、README、日志或产品地图。
- 管理接口统一从可信 Web UID/会话获取主体；不要把客户端传入的 openid 当作管理员身份。

## 投稿与纠错审核

建议状态：`pending → needs_more/rejected/published`。审核通过时，在同一事务中：

1. 校验标题、正文、图片和关联对象。
2. 创建或更新正式内容。
3. 更新投稿状态、审核者、审核时间和发布 ID。
4. 写入审计日志。

已完成审核的记录必须拒绝再次审核；已发布内容的“编辑”不能走待审草稿的同一状态迁移。删除要二次确认，服务端再次检查目标存在性和角色，并记录删除前摘要。

## 文件与图片

上传前限制 MIME、真实文件头、大小、数量、扩展名和目录；私有投稿图片与公开内容图片分桶/分目录。未审核 UGC 不应获得公开永久 URL。服务端生成短期访问地址或在审核界面通过受控接口读取。
